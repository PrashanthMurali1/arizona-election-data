# Browser HTTP caching

2026 Early Voting appears in the homepage's Live Elections tab. The retired early-voting, governor and attorney-general 2026 browser URLs remain not-found pages; their retained API endpoints are unchanged.

The browser HTTP cache owns response reuse, including across client-side navigation and document reloads. The former module-level activity/geography cache was removed: there was no benchmark demonstrating an additional benefit sufficient to justify its separate TTLs, eviction rules and SSE fallback. React retains only the currently mounted view and its last successful response for background-refresh error handling. There is no localStorage, IndexedDB or service worker.

| Resource | Response policy | Invalidation |
| --- | --- | --- |
| `/api/elections/az-2026-early-voting/activity` | `private, max-age=300, must-revalidate, no-transform`, content ETag | Reuse for five minutes; SSE revision changes and active five-minute checks force conditional revalidation immediately. |
| `/api/geography/{boundary_id}` | `private, max-age=86400, must-revalidate, no-transform`, content ETag | Reuse for 24 hours; next fetch after expiry validates. A different boundary ID uses a different URL. |
| Historical election APIs (Senate, House, Governor and Attorney General IDs through 2025, including special elections and their subresources) | `private, max-age=86400, must-revalidate, no-transform`, content ETag | Reuse for 24 hours; next fetch after expiry validates. |
| Other successful JSON data APIs, including catalog and retained live activity aliases | `private, no-cache, no-transform`, content ETag | Validate on each fetch so catalog and live election changes appear on next access. |
| Health, SSE, handled API errors | `no-store, no-transform` | Never reuse. SSE also sends `X-Accel-Buffering: no`. |
| Production `/assets/*` | `public, max-age=31536000, immutable` | Vite content hashes change asset URLs on rebuild. Only build-generated hashed assets belong here. |
| Production HTML / SPA routes | `no-cache` | Validate on navigation/reload so new builds supply new asset URLs. |

FastAPI sets API headers, including when accessed through the Vite development proxy. Caddy [preserves backend headers and sets a default only when absent](https://caddyserver.com/docs/caddyfile/directives/header), supplying `no-store, no-transform` when the backend supplies no policy (including unexpected errors). Cloudflare's existing `/api/` cache bypass should remain enabled: `private` permits browser storage while excluding shared caches. These are source changes; an existing deployment must be rebuilt/redeployed to receive them.

Normal `fetch` calls use `cache: "default"`. Mounting Live Elections always fetches activity and geography, letting the browser reuse fresh HTTP responses. During the mounted view, geography stays in view state; background activity updates do not reload geometry. On remount, geography goes through the HTTP cache again. The API can still compute/serialize the response on a conditional request; these ETags save response-body transfer, not database work. No backend response cache was added.

The ETag hashes the complete serialized JSON, including time-dependent stale flags. It is distinct from the SSE revision, which intentionally excludes age-only changes. An unchanged conditional GET returns a bodyless `304` with the same cache policy and ETag; the browser supplies the stored body to `fetch`. Changed content returns `200` and replaces the cached response. An importer/refresh needs no explicit purge: activity notifications trigger revalidation, historical election corrections appear after the 24-hour freshness window, other data APIs validate on access, and geometry changes under the same ID appear after its TTL. For immediate geometry changes, use a new boundary ID or explicitly reload with browser cache bypass. HTTP cache retention/eviction is browser-controlled; persistence is permitted, not guaranteed. See [MDN's fetch cache semantics](https://developer.mozilla.org/en-US/docs/Web/API/Request/cache).

While Live Elections is visible, one SSE connection compares notifications with the currently displayed activity revision. A different revision triggers `fetch` with `cache: "no-cache"`, which validates even a fresh cached response. A five-minute timer also revalidates without a revision change and retries failures. Duplicate revisions are skipped within the mounted view; notifications during a request coalesce, with a follow-up validation if a newer revision arrived while fetching. Hidden documents close SSE; visibility, focus and online events reconnect and recover missed revisions. Initial data loading does not wait for SSE. If the initial notification is unavailable, the normal HTTP fetch still loads the view and periodic revalidation continues.

The activity response atomically includes statewide/county metrics, registration breakdowns, provenance, failures and revision. Source report/retrieval timestamps never advance because of cache reuse. A local 30-second timer recomputes the 12-hour source stale threshold from those original timestamps, without requesting or changing figures. Background failures keep the mounted view with an error notice; failed checks do not update its successful-check time. On remount, expired HTTP responses must validate successfully and are not silently served as offline data. Leaving Live Elections aborts requests, closes SSE, removes timers/listeners and discards view state (including selection/sorting).

Verification includes isolated API policy/validator tests and a real Chromium test without request interception. The browser test checks fresh reuse, reuse after document reload, and forced validation producing a network `304` while JavaScript receives the cached JSON. Routed dashboard tests cover revision changes, coalescing, failures, reconnects, source age and cleanup; routing disables HTTP caching, so those tests count fetch calls and do not claim to measure HTTP-cache hits. No mutating production refresh is needed.

Review verification (October 29, 2026): frontend build, all nine frontend unit tests, the isolated HTTP-cache API test, and all 23 selected Chromium dashboard/cache checks passed. Chromium confirmed zero origin requests for fresh reuse before and after reload, and a bodyless network `304` on forced revalidation. The full backend suite reached 23 passes and 31 fixture setup errors because the retained `data/raw/us-house/calendar/vacancies-114.html` fails its existing source checksum; no source data was changed. Caddy runtime validation was unavailable because the local Docker daemon is stopped; its default-header syntax was checked against the official documentation. Production was not redeployed.

## Federal Elections prefetching

Opening Federal Elections prefetches only the currently selected office (Senate by default). Selecting House starts a House batch. Returning from another catalog tab uses the retained office choice. Senate batches request every catalog election's detail, counties and activity URLs, plus each unique boundary URL. House batches request every regular/special overview and each unique historical boundary URL. Each overview already contains all nine district rows, every contested district's candidates/results, sources and reconciliation, so separate district-detail requests are unnecessary for the existing House page. Prefetch and election pages use the same URL helper, adding the same `ui=<frontend-content-hash>` parameter to historical election and geography requests. The current catalog supplies five Senate elections and eight House elections, giving 16 distinct Senate URLs and 10 distinct House URLs.

Three workers consume and finish response bodies with normal `fetch(..., {cache: "default"})`. No JavaScript response cache, response timestamps, or persistent list of successful URLs is maintained. The browser decides whether to reuse, validate or download each URL. Geography is deduplicated within the batch and reused through the HTTP cache between batches. Cards and the dropdown remain usable throughout. Leaving the tab, switching offices, or navigating away aborts unfinished work; already completed successful responses stay eligible for HTTP-cache reuse. Each failed URL gets one retry per batch. Failed prefetches do not replace page content or prevent navigation. Re-entering the office or coming online starts another batch, allowing failed URLs to retry while successful fresh URLs are reused. Page navigation also loads normally if prefetching failed or was cancelled. There is no continuous background retry loop.

The 24-hour freshness period applies conservatively to federal contest/overview IDs dated through 2025, including all their JSON subresources. Future/current federal IDs keep validation on access until an appropriate live policy is introduced. The catalog itself continues validating on access, so navigating to a prefetched election can still validate the catalog, while its fresh election/map responses require no origin request. Live Elections behavior is unchanged. Historical State election APIs now share the same policy (see below).

A historical correction at an unchanged URL can remain cached for up to 24 hours after its last successful download/validation. Geography under an unchanged boundary ID can remain cached for 24 hours. Importing data does not purge browser caches. To obtain an urgent correction immediately, bypass/reload the browser cache or make the request with `cache: "no-cache"`; an ETag mismatch returns the replacement JSON. Frontend source/style/HTML changes generate a new `ui` value, so the next frontend load requests fresh election/map responses even within the previous 24-hour window. Old entries are bypassed rather than actively deleted. Clearing browser cache also forces a download on the next request. Browser eviction, disabled caching, private sessions or storage pressure can cause earlier refetches; prefetching does not guarantee offline availability.

The federal browser integration check runs against the real Mac preview with HTTP caching explicitly enabled and no request interception. It observes completed requests for all selected-office dependencies, verifies that Senate does not prefetch House, checks retained House selection on tab re-entry, visits every Senate and House election, and checks that those election/map URLs produce no additional origin responses during navigation. Queue unit checks cover shared-boundary deduplication, the three-request bound, partial-failure retries, cancellation and persistent failure limits.

Federal prefetch verification (October 29, 2026): the frontend build, all 12 frontend unit checks, the isolated cache-policy/ETag API check, and all 26 selected browser checks passed (the federal integration check was rerun after correcting the special-election row expectation). The real Chromium test confirmed the 24-hour/24-hour response policies, complete selected-office coverage, and zero additional origin responses for the prefetched election/map URLs while visiting every federal election. The updated backend was restarted at `127.0.0.1:8000` with the existing read-only snapshot; Vite serves the updated frontend at `http://127.0.0.1:5173`. This activation applies to the Mac preview; Windows production has not been redeployed.

## Frontend changes and cache versions

Historical election responses and geography both have a 24-hour freshness period. `cacheVersionPlugin.mjs` hashes the frontend source files and HTML into a deterministic version (test files are excluded). The shared `cacheUrl` helper adds that version to both prefetch and normal page requests. Any frontend source, component or style change conservatively invalidates all historical election/map responses once the updated frontend loads. Rebuilding unchanged source retains the same version. The development preview also reloads after a frontend edit so it picks up the new version. Live activity and catalog URLs keep their existing policies and are not versioned by this helper. The 2026 Governor/Attorney General live API aliases also retain validation on access.

A frontend update does not push into an already open production page; the new cache URLs take effect when that browser loads the updated frontend. Responses may be evicted by the browser before 24 hours. After 24 hours, an unchanged response can be renewed through an ETag/304 validation. Browser cache clearing or a new frontend version causes a cache miss and a new download. Run `node --test frontend/cacheVersionPlugin.test.mjs` to verify source/style/HTML version changes, unchanged-build reuse and development invalidation. The real federal browser test checks consistent version URLs across prefetch/navigation, a new download for a changed version, reuse of that new version, and a new download after clearing browser cache.

## State Elections prefetching

State Elections uses the same `electionPrefetch.ts` queue as Federal Elections. Opening the tab prefetches Governor by default; selecting Attorney General prefetches that office. The chosen office is retained while switching catalog tabs. Each batch fetches every catalog election's detail, counties and activity responses, plus each unique geography URL. The current historical catalog contains three Governor and three Attorney General elections (2014, 2018 and 2022), so each office has ten distinct dependency URLs, including the shared county boundary. Selecting one office does not prefetch the other. Shared geography is fetched once per batch and reused by the browser across offices and pages.

Historical Governor/Attorney General response URLs through 2025 receive the same `private, max-age=86400, must-revalidate, no-transform` policy and content ETags as federal responses. Both prefetching and normal election navigation use the existing frontend `ui` content version. A frontend update creates new cache URLs when loaded, cache clearing forces a download, and expiry after 24 hours permits conditional revalidation. Browser eviction can cause earlier downloads; complete prefetching does not guarantee offline availability. Historical corrections at unchanged URLs can remain cached for the remainder of the 24-hour window. Live 2026 aliases are excluded from this historical policy, so their validation behavior is preserved.

The shared queue limits work to three concurrent fetches, consumes response bodies to complete caching, deduplicates boundary URLs, retries each failed URL once, and aborts unfinished work when switching offices/tabs or leaving the catalog. Returning to an office, an online event, or normal page navigation can retry failures; completed successful responses remain eligible for reuse in the HTTP cache. No JavaScript response cache or success registry is retained.

The State browser integration check uses the running Mac preview with browser HTTP caching explicitly enabled and no request interception. It verifies all Governor and Attorney General dependency URLs and 24-hour headers, no unnecessary other-office prefetches, shared frontend version URLs, retained Attorney General selection, and zero additional origin responses for prefetched state election/map URLs while navigating every election. The existing federal and live checks remain part of regression validation. Queue tests cover both state offices as well as Senate for dependency selection, concurrency and partial-failure retries.

State prefetch verification (October 29, 2026): frontend build, all 16 frontend unit checks, the isolated cache-policy/ETag API check, and all 27 selected browser checks passed against `http://127.0.0.1:5173`. Chromium confirmed coverage of all three elections per state office, 24-hour policies and shared version URLs, and no additional origin responses for the prefetched state election/map URLs while visiting every Governor and Attorney General election. The backend was restarted with its existing read-only snapshot to activate the policy in the Mac preview. Windows production has not been redeployed.
