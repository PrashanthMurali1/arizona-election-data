# Browser HTTP caching

2026 Early Voting appears in the homepage's Live Elections tab. The retired early-voting, governor and attorney-general 2026 browser URLs remain not-found pages; their retained API endpoints are unchanged.

The browser HTTP cache owns response reuse, including across client-side navigation and document reloads. The former module-level activity/geography cache was removed: there was no benchmark demonstrating an additional benefit sufficient to justify its separate TTLs, eviction rules and SSE fallback. React retains only the currently mounted view and its last successful response for background-refresh error handling. There is no localStorage, IndexedDB or service worker.

| Resource | Response policy | Invalidation |
| --- | --- | --- |
| `/api/elections/az-2026-early-voting/activity` | `private, max-age=300, must-revalidate, no-transform`, content ETag | Reuse for five minutes; SSE revision changes and active five-minute checks force conditional revalidation immediately. |
| `/api/geography/{boundary_id}` | `private, max-age=86400, must-revalidate, no-transform`, content ETag | Reuse for 24 hours; next fetch after expiry validates. A different boundary ID uses a different URL. |
| Other successful JSON data APIs, including catalog and retained activity aliases | `private, no-cache, no-transform`, content ETag | Validate on each fetch so catalog changes and historical corrections appear on next access. |
| Health, SSE, handled API errors | `no-store, no-transform` | Never reuse. SSE also sends `X-Accel-Buffering: no`. |
| Production `/assets/*` | `public, max-age=31536000, immutable` | Vite content hashes change asset URLs on rebuild. Only build-generated hashed assets belong here. |
| Production HTML / SPA routes | `no-cache` | Validate on navigation/reload so new builds supply new asset URLs. |

FastAPI sets API headers, including when accessed through the Vite development proxy. Caddy [preserves backend headers and sets a default only when absent](https://caddyserver.com/docs/caddyfile/directives/header), supplying `no-store, no-transform` when the backend supplies no policy (including unexpected errors). Cloudflare's existing `/api/` cache bypass should remain enabled: `private` permits browser storage while excluding shared caches. These are source changes; an existing deployment must be rebuilt/redeployed to receive them.

Normal `fetch` calls use `cache: "default"`. Mounting Live Elections always fetches activity and geography, letting the browser reuse fresh HTTP responses. During the mounted view, geography stays in view state; background activity updates do not reload geometry. On remount, geography goes through the HTTP cache again. The API can still compute/serialize the response on a conditional request; these ETags save response-body transfer, not database work. No backend response cache was added.

The ETag hashes the complete serialized JSON, including time-dependent stale flags. It is distinct from the SSE revision, which intentionally excludes age-only changes. An unchanged conditional GET returns a bodyless `304` with the same cache policy and ETag; the browser supplies the stored body to `fetch`. Changed content returns `200` and replaces the cached response. An importer/refresh needs no explicit purge: activity notifications trigger revalidation, other data APIs validate on access, and geometry changes under the same ID appear after its TTL. For immediate geometry changes, use a new boundary ID or explicitly reload with browser cache bypass. HTTP cache retention/eviction is browser-controlled; persistence is permitted, not guaranteed. See [MDN's fetch cache semantics](https://developer.mozilla.org/en-US/docs/Web/API/Request/cache).

While Live Elections is visible, one SSE connection compares notifications with the currently displayed activity revision. A different revision triggers `fetch` with `cache: "no-cache"`, which validates even a fresh cached response. A five-minute timer also revalidates without a revision change and retries failures. Duplicate revisions are skipped within the mounted view; notifications during a request coalesce, with a follow-up validation if a newer revision arrived while fetching. Hidden documents close SSE; visibility, focus and online events reconnect and recover missed revisions. Initial data loading does not wait for SSE. If the initial notification is unavailable, the normal HTTP fetch still loads the view and periodic revalidation continues.

The activity response atomically includes statewide/county metrics, registration breakdowns, provenance, failures and revision. Source report/retrieval timestamps never advance because of cache reuse. A local 30-second timer recomputes the 12-hour source stale threshold from those original timestamps, without requesting or changing figures. Background failures keep the mounted view with an error notice; failed checks do not update its successful-check time. On remount, expired HTTP responses must validate successfully and are not silently served as offline data. Leaving Live Elections aborts requests, closes SSE, removes timers/listeners and discards view state (including selection/sorting).

Verification includes isolated API policy/validator tests and a real Chromium test without request interception. The browser test checks fresh reuse, reuse after document reload, and forced validation producing a network `304` while JavaScript receives the cached JSON. Routed dashboard tests cover revision changes, coalescing, failures, reconnects, source age and cleanup; routing disables HTTP caching, so those tests count fetch calls and do not claim to measure HTTP-cache hits. No mutating production refresh is needed.

Review verification (October 29, 2026): frontend build, all nine frontend unit tests, the isolated HTTP-cache API test, and all 23 selected Chromium dashboard/cache checks passed. Chromium confirmed zero origin requests for fresh reuse before and after reload, and a bodyless network `304` on forced revalidation. The full backend suite reached 23 passes and 31 fixture setup errors because the retained `data/raw/us-house/calendar/vacancies-114.html` fails its existing source checksum; no source data was changed. Caddy runtime validation was unavailable because the local Docker daemon is stopped; its default-header syntax was checked against the official documentation. Production was not redeployed.
